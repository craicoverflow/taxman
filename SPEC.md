# taxman — Specification

Source idea: [`docs/ideas/taxman.md`](docs/ideas/taxman.md). This spec reflects the codebase as it stands (Phases 0–8 built; dashboard charts §7 and tax-year selector §8 built 2026-09-05; see `tasks/todo.md`) plus the next confirmed feature (§9). Where an item remains an unresolved "Open Question" or unverified assumption, this spec either resolves it or carries it forward explicitly as a blocking task (tax-rule mechanics that need a Revenue TDM citation before implementation).

---

## 1. Objective

### Problem
Replace a manually maintained spreadsheet with a trustworthy, self-hosted, always-on ledger that turns raw exports from Degiro, IBKR, ETRADE, and N26 into running DIRT, CGT, and exit-tax/deemed-disposal figures — with a full audit trail — without requiring a part-time tax analyst every January.

### Target user
Enda, personally. Single-user tool. Not designed, licensed, or hardened for anyone else's tax liability (see [§6 Boundaries](#6-boundaries) and Non-goals below).

### Success criteria
- A single command starts a local web UI showing merged P&L and running tax liability (CGT / exit tax / DIRT) across all four platforms, computed from ingested CSV exports.
- Every figure traceable via `internal/audit` resolves back to the specific source transactions and the specific versioned tax rule that produced it. (The live dashboard summary is a documented exception — see §7 — computed fresh on every request rather than persisted per view.)
- The system flags any holding it cannot confidently classify (CGT asset vs. exit-tax fund) instead of guessing.
- Re-uploading an export that overlaps previously ingested data does not double-count transactions.
- Deemed-disposal anniversaries (8 years from each fund-lot acquisition) are tracked; surfacing them proactively in the UI is not yet built (see §9 Out of scope, and blocked task 4.9).
- The dashboard shows P&L and liability visually (charts), not just as numbers, and N26 interest payments can be logged by hand without waiting on a PDF export (§7).
- A separate portfolio page answers "what is this worth today, and where am I up or down per position" from live market prices, in euro, degrading to last-known prices when offline (§9).
- Output numbers are cross-checked against the existing hand-built spreadsheet and, where feasible, an independent Tax-Wizard run, before being trusted for filing.

### Non-goals (v1)
Dividend/distribution income tracking, multi-user/SaaS support, broker API integrations beyond a possible future IBKR Flex Query, ROS e-filing, and any LLM-performed tax arithmetic. A deemed-disposal deadline timeline and any historical portfolio-value-over-time chart are deferred past the current dashboard/portfolio pass (§9). See [§6](#6-boundaries) for how the core list is enforced as a hard boundary, not just deferred scope.

## 2. Domain Model

These concepts recur across ingestion, computation, and storage.

| Concept | Definition |
|---|---|
| **Transaction** | A single raw event from a platform export: buy, sell, dividend (recorded but unprocessed in v1), RSU vest, interest credit. Immutable once ingested. |
| **Fingerprint** | A deterministic hash of a transaction's identifying fields (platform, date, ticker/ISIN, quantity, price, currency) used to detect duplicates across overlapping uploads. Ingestion is idempotent by fingerprint. |
| **Holding** | A distinct security/instrument (by ISIN or platform-specific ID) with a **Classification**: `CGT_ASSET` (individual equity, RSU shares) or `EXIT_TAX_FUND` (UCITS/offshore fund), or `UNCLASSIFIED` — blocking state, requires manual resolution before any tax computation touches that holding's lots. |
| **Lot** | A specific acquisition of a holding (quantity + cost basis + acquisition date + currency, converted to EUR at transaction-date ECB reference rate — `internal/fx`). The unit that FIFO/s.581 matching and deemed-disposal tracking operate on. |
| **Disposal** | A sale (real) matched against one or more lots via FIFO; carries `Date`, `Quantity`, `Proceeds`, `CostBasis`, `Gain`. Deemed disposal (synthetic, generated by the 8-year clock) is tracked for anniversary dates (task 4.7) but not yet turned into a liability figure — blocked, see 4.9. |
| **Rule Version** | A tax rate or rule (CGT rate, exit tax rate, DIRT rate, annual exemption, s.581 parameters) scoped to an effective-date range, looked up in `internal/taxrules` by the date of the relevant event — never a bare hardcoded constant in `engine`. A rate can be overridden at runtime by env var (`TAXMAN_CGT_RATE` / `TAXMAN_EXIT_TAX_RATE` / `TAXMAN_DIRT_RATE`, set to a fraction like `0.38`); the override replaces that rate for all event dates, so it is only correct when every figure being computed falls under the new rate. |
| **Audit Record** | Links a computed liability figure to the disposal event(s), lot(s), and rule version(s) that produced it (`internal/audit`). Every figure `taxman report` or the golden-fixture tests produce resolves to one of these; the live dashboard summary is the one exception, documented in §7. |
| **Ticker Mapping** | A user-supplied association between a ledger instrument (the raw name/ISIN key holdings are stored under) and a market symbol a price provider understands. Only holdings with a mapping are priced (§9). Held in `internal/db` (`instrument_tickers`), edited only through the portfolio page — never inferred from the instrument name or ISIN. |
| **Quote** | A last-price-per-share figure for a market symbol, in the instrument's native currency, from a public price provider, with a fetched-at timestamp. Cached; converted to EUR via `internal/fx` before display. Never persisted to `internal/audit` and never used by `internal/engine`. |

## 3. Commands

Binary name: `taxman`. Single Go binary, `cmd/taxman/main.go` entrypoint, subcommands via standard library `flag`-based dispatch.

| Command | Purpose |
|---|---|
| `taxman serve [--port 8080] [--db path]` | Starts the local HTTP server + dashboard UI against a SQLite DB. Default mode for day-to-day use. The dashboard (`/`) takes an optional `?year=YYYY` query param that scopes every figure (liability summary, holdings P&L, charts) to one calendar/Irish tax year; omitted means all years. The server also exposes `/portfolio` (§9), a live market-value view that ignores `?year=`. |
| `taxman import <file> [--platform degiro\|ibkr\|etrade\|n26] [--dry-run]` | Ingests one CSV export. Auto-detects platform from header shape if `--platform` omitted; refuses to guess silently if detection is ambiguous. `--dry-run` reports what would be ingested/deduped without writing. |
| `taxman backfill <dir>` | One-time historical backfill: ingests every file in a directory (mixed platforms, auto-detected). Distinct from `import` so the operational difference between "loading history" and "adding this month's export" is explicit in the audit log. |
| `taxman classify [--list-unclassified] [--set <isin> <CGT_ASSET\|EXIT_TAX_FUND>]` | Manages the holding classification override table. `--list-unclassified` surfaces anything blocking computation. |
| `taxman report --year <YYYY> [--format text\|json]` | Generates a point-in-time report for a tax year: liability by category, audit trail references. `--format pdf` is not built (ask-first item, §6). Does not yet persist its own audit records (see `cmd/taxman/report.go`). |
| `taxman validate --fixture <path>` | Runs the computation engine against a golden fixture and diffs against expected output. Used both in CI and for one-off validation against spreadsheet/Tax-Wizard cross-check numbers (§5). |
| `taxman migrate [up\|down]` | Applies/rolls back SQLite schema migrations. |

Development commands (`Makefile`):

```
make build           # go build -o bin/taxman ./cmd/taxman
make test            # go test -race ./... (includes the features/ BDD suite)
make lint            # golangci-lint run
make fuzz            # go test -fuzz=Fuzz -fuzztime=60s ./internal/engine/...
make bdd             # run features/*.feature (godog) with readable output — §14
make regen-features  # rebuild the engine-pinned figures in features/*.feature — §14
make docs            # render docs/maths.md + features/ to docs/maths.html — §14
make ci              # build + test + check-features + lint, what CI runs
make dev             # runs `taxman serve` under air, rebuild+restart on .go changes
```

## 4. Project Structure

Standard Go project layout (`cmd/` + `internal/`), organized around the domain model in §2.

```
taxman/
├── cmd/
│   └── taxman/                   # CLI entrypoint + one file per subcommand
├── internal/
│   ├── ledger/                   # append-only transaction store; fingerprinting/dedup
│   ├── ingest/
│   │   ├── route.go               # shared platform-detection/parsing dispatch
│   │   ├── degiro/                 # Degiro Transactions + Account (cash-ledger) CSV parsers
│   │   ├── ibkr/                   # IBKR CSV: flat trades export (real, FX via FXRateToBase — ADR 0002) + Activity Statement (unverified)
│   │   ├── etrade/                 # ETRADE parser incl. RSU vest records; NewRSUVest manual entry (§11)
│   │   ├── n26/                    # N26 interest: manual entry only (no clean CSV export — §7)
│   │   ├── traderepublic/          # Trade Republic interest: manual entry only (§10)
│   │   └── interest/               # registry of hand-entered interest sources (§10)
│   ├── classify/                  # holding classification + manual override table
│   ├── taxrules/                  # versioned rates/rules by effective date
│   ├── engine/                    # FIFO lot matching, CGT/DIRT/exit-tax computation, deemed-disposal clock
│   ├── fx/                        # ECB reference-rate EUR conversion for non-EUR transactions
│   ├── prices/                    # live market-quote client: provider + fallback, in-process cache, staleness (§9). No engine/audit dependency.
│   ├── audit/                     # links computed figures back to transactions + rule versions
│   ├── web/                       # HTTP handlers, dashboard + portfolio templates (html/template, no build step)
│   └── db/                        # SQLite schema + migrations (embedded)
├── testdata/
│   ├── golden/                    # golden fixtures: synthetic input + expected output pairs
│   └── fixtures/                  # synthetic per-platform sample exports (never real data — §6)
├── docs/
│   ├── ideas/taxman.md            # source idea doc
│   └── adr/                       # architecture decision records (e.g. 0001-fx-conversion.md)
├── tasks/
│   ├── plan.md                    # detailed task breakdown, acceptance criteria, checkpoints
│   └── todo.md                    # checklist view of plan.md
├── SPEC.md                        # this file
├── README.md
├── Makefile
├── go.mod / go.sum
└── .gitignore                     # excludes real data: /data, *.local.*, *.db, /bin
```

**Why this shape:** `taxrules` and `engine` are the two packages doing the actual tax-law work and are the ones with unverified mechanics (s.581, deemed-disposal credit/refund) — keeping them free of ingestion/web dependencies means their tests run as pure functions over lots and dates, which is what makes golden-fixture TDD practical. `ingest/*` subpackages are per-platform rather than one generic parser, since each platform's export format is a distinct, independently-changing contract; `ingest/route.go` holds only the detection/dispatch logic shared across them. `prices` is a new sibling of `fx`: a leaf package the web layer calls, deliberately isolated from `engine` and `audit` so that a network dependency can never reach tax computation or the audit trail.

## 5. Testing Strategy

**Discipline: TDD with golden-file tests.** No tax-rule logic is written before a failing test exists for it.

- **Unit tests** colocated as `_test.go` files, table-driven per Go idiom. Every function in `taxrules` and `engine` gets direct test coverage, not just integration-level coverage.
- **Golden fixtures** (`testdata/golden/`), one per distinct tax scenario, built so far:
  - CGT disposal, simple FIFO, no complications
  - CGT disposal with a non-EUR transaction requiring FX conversion
  - CGT year-level aggregation: two holdings disposed in one year share a **single** €1,270 exemption (`cgt_year_single_exemption`) — not one exemption per holding
  - CGT loss carry-forward: a net loss in one year is set against a later year's gain, restricted so the annual exemption is not wasted (`cgt_loss_carryforward`, s.601(4))
  - Exit-tax fund, actual disposal before any deemed disposal has occurred
  - Exit-tax rate transition: a fund straddling the 41%→38% rate change resolves to the correct rate by event date, not ingestion date
  - Exit-tax, no loss relief per chargeable event: a losing disposal does not net against a gaining disposal of the same fund/year (`exittax_no_intra_fund_netting`)
  - RSU vest followed by later disposal, cost basis = vest-date FMV
  - DIRT on interest, straightforward
  - DIRT at a historical rate: a backfilled pre-2020 credit resolves to that year's DIRT rate, not today's (`dirt_historical_rate`)
  - Duplicate ingestion: re-importing a file (or an overlapping export) produces zero additional transactions
  - Unclassified holding: computation refuses to run / clearly errors rather than silently defaulting a classification

  Computed tax figures (CGT, exit tax, DIRT) are rounded **down to whole euro** — the Revenue self-assessment convention (`internal/engine/round.go`); gains, proceeds and loss pools stay at full decimal precision.

  **Still blocked, not yet buildable:** CGT disposal with a repurchase inside the s.581 four-week window (loss restriction), and exit-tax deemed disposal + later actual-disposal credit/refund — both need a Revenue TDM citation before the expected-output side of the fixture can be written (task 4.8/4.9). Current behaviour, pinned in `features/known_limitations.feature` and described in `docs/maths.md` §11: the s.581 window is matched as **plain FIFO** with the loss un-restricted (no error is raised — a return covering a four-week repurchase must be adjusted by hand), and deemed disposal is a **date-tracking clock only** (`NextDeemedDisposalAnniversary`), with no liability figure or credit/refund path built. Neither shortcut may be turned into a computed figure without a cited source.
- **Cross-validation against real data stays local, not committed.** The existing spreadsheet and any Tax-Wizard parallel-run numbers are real financial data — per §6 they never enter the repo. Golden fixtures use fabricated amounts reproducing the same *structural* scenario (same date deltas, same rate boundaries, same matching edge cases); real numbers are validated locally via `taxman validate` against a gitignored local fixture directory, with the mapping documented in `docs/adr/`.
- **Fuzz testing** (Go native `testing.F`) on the lot-matching engine — feed random sequences of buy/sell events and assert invariants (total quantity conserved, no negative lots, every disposal resolves to a rule version). Wired via `make fuzz`; not required in `make test`/CI, run before any change to `engine/`.
- **Integration tests**: full pipeline (import synthetic fixture CSVs → classify → compute → generate report) against a temporary SQLite DB, including cross-platform overlap (e.g. Degiro + IBKR sharing an ISIN).
- **Web tests** (`internal/web/*_test.go`): `httptest`-based, table-driven, asserting handler status codes, redirects, form-validation errors, and rendered HTML content — not pixel/visual rendering.
- **`internal/prices` tests**: the provider client is tested against an `httptest.Server` returning canned provider responses (success, HTTP error, malformed body, timeout) — no real network in `make test`. Assert: primary success, fallback on primary failure, cache hit inside TTL, stale value returned (with staleness flagged) when every provider fails, and native→EUR conversion via a stubbed rate. The portfolio handler test uses a fake quote source (interface, not the real HTTP client) so web tests stay offline and deterministic.
- **Executable maths spec** (`features/*.feature`, godog — §14): plain-English Gherkin worked examples for every engine calculation, with the `Then`-step figures generated by the engine and pinned in place (`make regen-features`). Runs in `make test`; `make ci` fails if the pinned figures are stale (drift gate). The prose companion is `docs/maths.md`, each rule carrying its Irish tax-law citation.
- **CI** (`make ci`): `go test -race ./...` (incl. `features/`), `make check-features` (feature-figure drift gate), `golangci-lint run`, build. Coverage tracked, not gated at v1 — golden-fixture and worked-example completeness matter more than percentage coverage.

## 6. Boundaries

### Always do
- Keep tax rates/rules in `internal/taxrules` as data keyed by effective date — never a bare hardcoded constant in `engine`. A runtime env-var override (see §2 Rule Version) is the one sanctioned way to change a rate without a code change; it lives in `taxrules`, not scattered through callers.
- Show monetary figures in the dashboard and portfolio page in euro (`€`, two decimals) — every figure the engine emits is already EUR-converted at transaction-date ECB rates; live quotes (§9) are converted to EUR via `internal/fx` before display.
- Keep per-tax-year splitting (which disposals count, which year's rate/exemption applies) in `internal/engine` — `cmd/taxman/report.go` and the dashboard's `?year=` selector both call it rather than re-deriving the split. CGT is aggregated at the year level across every CGT_ASSET holding by `engine.AggregateCGTYear` (one €1,270 exemption per year, gains/losses netted across holdings per TCA s.31, unused losses carried forward per s.601(4)); exit tax and DIRT stay per-holding (`ComputeExitTaxForYear` / `ComputeDIRTForYear`).
- Add or extend a golden-fixture test in the same change that adds or modifies any logic in `taxrules` or `engine`.
- Produce an `audit` record for every computed liability figure, linking it to source transactions and the rule version applied — the live dashboard summary is the one documented exception (§7).
- Run `make ci` before considering any change complete.
- Keep `.gitignore` covering real data paths (`/data`, `*.local.*`, `*.db`, `/bin`, any directory holding actual exports) and verify new file types added to the project don't accidentally fall outside it.
- Flag/block on an `UNCLASSIFIED` holding rather than defaulting it to either classification.

### Ask first
- Before implementing the s.581 matching mechanics or deemed-disposal credit/refund logic without a cited Revenue TDM source — surface the citation for confirmation before writing the expected-output side of those fixtures.
- Before adding any new external dependency, especially anything capable of making network calls. (A CDN-loaded `<script>` in the web UI, per §7, is not a `go.mod` dependency and does not trigger this. The `internal/prices` client in §9 uses only `net/http` from the standard library — a new provider SDK would trigger this.)
- Before a DB schema change that isn't backward-compatible with already-ingested ledger history.
- Before committing or pushing to git (standing instruction, not specific to this project).
- Before implementing anything listed under Non-goals above, even as a "small addition" — confirm scope has actually changed rather than assuming a non-goal has become in-scope.
- Before building the `report --format pdf` output, the deemed-disposal deadline timeline, or a historical portfolio-value-over-time chart — all currently deferred, not just unimplemented by omission.
- Before adding a price provider that requires an API key, account, or any credential **beyond the one already sanctioned**: Finnhub, enabled only by the `TAXMAN_FINNHUB_TOKEN` env var, off by default, sending only the symbol + token (§9). Any second credentialed provider, or widening what Finnhub sends, is ask-first.

### Never do (no exceptions, not just "ask first")
- Commit real CSVs, real account data, or any real financial figures to git. Fixtures and test data are synthetic/fabricated only.
- Send real account data — holdings quantities, cost basis, balances, transactions, account identifiers, or the ledger itself — to any external network service or API, including AI/LLM APIs, without explicit per-instance approval at the time. The §9 price client sends only a market ticker symbol the user typed into the mapping form and, when `TAXMAN_FINNHUB_TOKEN` is set, that token. Quantities and cost basis are joined to quotes locally, after the fetch, and never leave the process.
- Build any code path that submits or files data to Revenue/ROS or any government system.
- Let an LLM or chat layer perform tax arithmetic. It may only explain figures already computed deterministically by `engine`, tracing the existing audit record — it never produces a number itself.
- Silently guess a holding's tax classification when it's ambiguous or unrecognized.
- Infer or auto-populate a ticker mapping (§9) from an instrument name or ISIN — a wrong guess silently misprices the portfolio. Mappings are user-entered only.

## 7. Feature: Dashboard Charts & Manual Interest Entry

**Status:** built (2026-09-05).

### Objective
The dashboard (`internal/web`) rendered P&L and liability as plain HTML tables/text. This pass replaced the two figures that matter most for at-a-glance use with charts, and closed a real gap: `internal/ingest/n26.NewInterestCredit` existed but was wired to no CLI command or HTTP route, so there was no way to record an N26 interest payment at all (N26 has no clean CSV export — manual entry is the only path, by design, not a stopgap).

### In scope
- **P&L-over-time chart**: cumulative realized gain, built from `engine.CGTResult`/`ExitTaxResult` `Disposal.Date`/`.Gain` across every classified holding in the ledger, sorted by date and accumulated. Computed fresh per request in `internal/web`, same as the existing dashboard summary — no new engine code.
- **Liability-by-tax-type chart**: CGT / exit-tax / DIRT amounts due, from the existing `dashboardSummary` fields, rendered as a chart instead of (or alongside) the current text.
- **`POST /interest` handler**: form fields `date` (`YYYY-MM-DD`) and `amount` (positive decimal); currency fixed to `EUR`. Validates via `n26.NewInterestCredit`, inserts via `ledgerStore.Insert`, redirects `303` to `/` on success, `400` with a message on validation failure — mirroring the existing `handleClassify` pattern (`internal/web/server.go`).
- A form on the dashboard page for the above, following the existing inline-`html/template` style (no separate template files, no client-side framework).

### Out of scope (this pass)
- Holdings-allocation chart, deemed-disposal deadline timeline chart — the allocation view is now §9; the timeline stays deferred (§1, §6).
- Multi-account/multi-institution interest tracking — N26 only, single instrument (`N26_SAVINGS`), as today. (Extended to per-source instruments in §10.)
- Any change to `internal/engine` — this is purely a `internal/web` presentation and ingestion-entry-point change.
- Persisting dashboard chart figures to `internal/audit` — same live-computed, not-persisted status as the rest of the dashboard summary (§1, §6).

### Tech stack addition
Chart.js (UMD build), loaded via a `<script src="https://cdn.jsdelivr.net/npm/chart.js@…">` tag in the dashboard template. No `go.mod` addition, no JS build step or package manager — data is marshaled to JSON server-side and embedded in the page for the inline JS to read and initialize the charts.

### Code style
Follows the existing handler pattern in `internal/web/server.go`, e.g.:

```go
func (s *Server) handleInterest(w http.ResponseWriter, r *http.Request) {
	if r.Method != http.MethodPost {
		w.Header().Set("Allow", http.MethodPost)
		http.Error(w, "method not allowed", http.StatusMethodNotAllowed)
		return
	}
	if err := r.ParseForm(); err != nil {
		http.Error(w, fmt.Sprintf("parsing form: %v", err), http.StatusBadRequest)
		return
	}

	tx, err := n26.NewInterestCredit(r.FormValue("date"), r.FormValue("amount"), "EUR")
	if err != nil {
		http.Error(w, fmt.Sprintf("interest: %v", err), http.StatusBadRequest)
		return
	}
	if _, err := s.ledgerStore.Insert(tx); err != nil {
		http.Error(w, fmt.Sprintf("interest: inserting: %v", err), http.StatusInternalServerError)
		return
	}
	http.Redirect(w, r, "/", http.StatusSeeOther)
}
```

### Testing strategy
- `internal/web/server_test.go`: table-driven tests for `handleInterest` (valid entry → redirect + ledger row present; invalid date/amount → 400; wrong method → 405), following the existing `handleClassify` test shape.
- Dashboard test asserts the chart-data JSON block is present and its shape matches what the client-side JS expects (data present and correctly derived from a fixture ledger), not the rendered chart pixels.

### Boundaries specific to this feature
- **Always**: keep chart-data assembly in `internal/web`, not `internal/engine` — no tax-rule logic moves.
- **Ask first**: before this diverges from a CDN-script pattern into any bundler/build step. (Extending interest entry beyond N26 was the ask; done in §10 — still EUR-only.)
- **Never**: send ledger data to the CDN — the Chart.js script tag fetches only the library file, chart data stays server-rendered into the page.

## 8. Feature: Dashboard tax-year selector

**Status:** built (2026-09-05).

### Objective
Let the dashboard be scoped to a single tax year — "how much was/is owed in 2024 vs 2025" — instead of only an all-time aggregate.

### Shape
- `GET /?year=YYYY` scopes the liability summary, holdings P&L, and both charts to disposals/interest dated in that calendar (Irish tax) year; omitted or empty `year` is the all-years view (unchanged default). An unparseable or out-of-range year is `400`, not a silent fallback.
- A `<select>` on the page (auto-submitting GET form, `<noscript>` fallback button) lists "All years" plus every year that has a transaction, most recent first.
- Per-year computation lives in `internal/engine`. CGT: `engine.CGTDisposals` FIFO-matches each holding's full acquisition history, then `engine.AggregateCGTYear` nets every CGT_ASSET holding together for the selected year — one €1,270 exemption, cross-holding gain/loss netting, brought-forward losses (s.601(4)), rate resolved at 31 Dec. Exit tax / DIRT: `ComputeExitTaxForYear` / `ComputeDIRTForYear`, per holding. `cmd/taxman/report.go` and the dashboard both call these; neither re-derives the split.

### Out of scope
- Multi-year ranges or arbitrary date windows — one whole year at a time.
- Persisting per-year figures to `internal/audit` (same live-computed status as the rest of the dashboard, §1/§6).

## 9. Feature: Portfolio page (live market value)

**Status:** confirmed intent (interview-me, 2026-09-05), not yet built. Supersedes the previously deferred "holdings-allocation chart" non-goal — scope has changed by explicit decision.

### Objective
The dashboard answers "what do I owe". It never answers "what is this worth today, and where am I up or down". That needs live prices, which the tool has never had. This feature adds a **separate page** — `GET /portfolio` — with two visuals over currently-held, ticker-mapped positions, all in euro:

1. **Allocation pie** — current market value (live price × quantity held) split by product; each slice one instrument, plus a headline total.
2. **Cost-vs-value bars** — one group per product: total cost basis (net of disposals) vs current market value. The gap is unrealised gain/loss. Sorted by position value, descending.

### In scope
- **`internal/prices` package**: a quote client with an ordered provider chain.
  - Providers, tried in order:
    1. **Finnhub** (`finnhub.io/api/v1/quote` + `/stock/profile2` for currency) — used **only** when `TAXMAN_FINNHUB_TOKEN` is set. Keyless-by-default is the design; this one credentialed provider is a sanctioned opt-in (§6) because the keyless endpoints are rate-limited or IP-blocked on some networks. Only the ticker symbol and the token leave the process — no ledger data.
    2. **Yahoo Finance** chart endpoint (`query1.finance.yahoo.com/v8/finance/chart/<symbol>`) — no key, no crumb/cookie handshake (unlike `v7/finance/quote`).
    3. **stooq** (`stooq.com/q/l/?s=…&f=sd2t2ohlcv&e=csv`) — no key; reports a price but no currency.
  - In-process cache keyed by symbol, TTL ~15 min. A cache hit inside TTL makes no request. Finnhub listing currencies are cached separately (a listing's currency never changes).
  - On every provider failing: return the last cached quote with a `Stale bool` / `AsOf time.Time` set, never an error that blanks the page. With no cached value at all, that symbol is reported as "unpriced" and excluded from totals. A quote whose currency is unknown (stooq, or a Finnhub profile miss) is likewise treated as unconvertible unless it is already EUR.
  - `net/http` + `encoding/json` + `encoding/csv` + `os` (env read) — no new `go.mod` dependency.
  - Exposes an interface (e.g. `Quoter`) so `internal/web` can be tested against a fake.
- **`instrument_tickers` migration** (`internal/db/migrations/0005_*`): `instrument` (PK, the ledger's instrument key) → `symbol` (text), plus `created_at`. Backward-compatible additive table; no change to `transactions` or existing rows.
- **`engine.OpenPositions`**: `func OpenPositions(txs []ledger.Transaction) (OpenPosition, error)` where `OpenPosition{Quantity, CostBasis decimal.Decimal}`. Runs the same FIFO consumption as `matchDisposalsFIFO` but returns the surviving lots' summed quantity and cost basis instead of the disposals. Non-EUR lots restated in euro at transaction-date ECB rate, same as `ComputeCGT`. Used by the portfolio handler for the cost-basis bar.
- **`GET /portfolio` handler**: builds the current holdings set (`OpenPosition.Quantity > 0`, per instrument via `engine.OpenPositions`), joins to `instrument_tickers`, fetches quotes for mapped symbols, converts native→EUR via `fx.Rate`, assembles pie + bar data, renders inline `html/template` in the existing style. Ignores `?year=` entirely. Chart.js via the same CDN `<script>` pattern as §7.
- **Inline mapping form**, one per unmapped held instrument, `POST /portfolio/ticker` (fields `instrument`, `symbol`), validates non-empty, upserts the row, `303` back to `/portfolio` — mirrors `handleClassify`. Unmapped instruments are listed in their own section and excluded from both charts and the total.
- **Staleness / gaps surfaced, not hidden**: a "prices as of HH:MM" stamp; per-position marker when a quote is stale; the unpriced/unmapped list visible on the page.

### Out of scope (this pass)
- Historical portfolio-value-over-time (any time series) — deferred (§1, §6).
- Intraday auto-refresh, websockets, server push — page is accurate as of last load.
- Pricing cash, N26 savings, deposits, or any interest-bearing balance — no market price exists; these never appear.
- Auto-guessing a ticker from instrument name or ISIN — user-entered mappings only (§6).
- Any change to `internal/taxrules` or `internal/audit`. Quotes are never persisted as audit records and never feed tax computation.
- Any change to `internal/engine` **beyond one additive, read-only function**: `engine.OpenPositions(txs) (OpenPosition, error)`, returning the still-held quantity and the FIFO cost basis of the remaining lots for one instrument. The FIFO matcher already computes lot `Remaining` internally and discards it; this exposes it. No tax-rule logic, no rate lookup, no new golden fixture — a unit test over buy/sell sequences (quantity conserved, basis = sum of surviving lots) is sufficient. The portfolio page calls it; no lot-matching logic lives in `internal/web`.
- Touching the existing dashboard (`/`) or its charts.
- Multi-currency display toggle — EUR only.

### Tech stack addition
`internal/prices` uses the Go standard library only. Chart.js as in §7 (no new front-end tooling). No credential storage in code: the optional Finnhub token is read from the `TAXMAN_FINNHUB_TOKEN` environment variable at process start (same mechanism as the `TAXMAN_*_RATE` overrides) and never written anywhere. For local dev, `make` loads a gitignored `.env` (see `.env.example`) and exports it, so `make dev` picks the token up; the token itself is never committed.

### Code style
Handler mirrors `handleClassify` / `handleInterest` in `internal/web/server.go` (method guard → `ParseForm` → validate → store → `303`). Quote fetching is isolated behind an interface so the handler takes a `prices.Quoter`, not an HTTP client:

```go
// Quoter returns the latest known price per share for a market symbol,
// in the symbol's native currency. A returned Quote may be Stale (a
// cached value served because every provider failed); callers show the
// AsOf time rather than treating stale as an error.
type Quoter interface {
	Quote(ctx context.Context, symbol string) (Quote, error)
}

type Quote struct {
	Symbol   string
	Price    decimal.Decimal
	Currency string
	AsOf     time.Time
	Stale    bool
}
```

EUR conversion reuses `fx.Rate(currency, time.Now())`; monetary output is `€`, two decimals, matching the dashboard (§6).

### Testing strategy
- `internal/prices/*_test.go`: `httptest.Server` with canned responses — primary success; primary 5xx → fallback used; both fail + cached value → stale Quote returned; both fail + no cache → error surfaced to caller as "unpriced"; cache hit inside TTL issues no request; native→EUR via stubbed rate.
- `internal/web/server_test.go`: `/portfolio` handler tested with a fake `Quoter` (no network). Cases: mapped holdings → pie + bar JSON shape correct and EUR-converted; unmapped holding → appears in the unmapped list, absent from totals; stale quote → staleness surfaced in rendered HTML; `POST /portfolio/ticker` valid → `303` + row present; empty symbol → `400`; wrong method → `405`; `?year=` present → ignored (same output as without).
- `internal/engine/*_test.go`: unit test for `OpenPositions` — table-driven over buy/vest/sell sequences: all-open (no sells) → quantity and basis equal total acquired; partial FIFO consumption → surviving-lot quantity and basis correct, oldest consumed first; fully disposed → zero; oversell → same explicit error `matchFIFO` already returns; non-EUR lot → basis restated in euro. No golden fixture (no tax-rule logic, no rate/exemption).

### Boundaries specific to this feature
- **Always**: keep `internal/prices` free of any `engine`/`audit`/`ledger` import — it is a leaf utility like `fx`. Convert every quote to EUR before it reaches a template. Show the price timestamp and the unmapped/unpriced list on the page.
- **Ask first**: before adding a provider that needs a key/account; before adding a `go.mod` dependency for price fetching; before persisting quotes anywhere beyond the in-process cache; before adding any historical/time-series storage.
- **Never**: send anything but the ticker symbol (and, if set, the Finnhub token) outbound — no quantities, cost basis, account IDs, or ledger rows. Never infer a mapping from instrument metadata. Never let a price-fetch failure blank the page or block the dashboard. Never log or persist the token.

## 10. Feature: Multi-source manual interest entry

**Status:** built (2026-09-06). Resolves §7's "ask first before extending interest entry beyond N26" item.

### Objective
The "Log interest payment" form only ever produced an N26 credit. Other savings accounts pay DIRT-liable interest with no clean CSV export either — Trade Republic first — and needed the same manual path.

### Shape
- `internal/ingest/interest` is a registry of hand-entered interest **sources**. Each `Source` has a stable wire `Key`, a display `Label`, a `ledger.Platform`, and a builder (`Source.NewCredit(date, amount)`, EUR fixed). N26 stays first and is the default when a request omits `source`.
- Per source, a distinct `ledger.Platform` and a distinct fixed instrument id (`N26_SAVINGS`, `TRADE_REPUBLIC_SAVINGS`) so the two never collapse into one dashboard holding. Per-platform builders live in `internal/ingest/{n26,traderepublic}`, unchanged in shape.
- `POST /interest` and `POST /interest/update` take an extra `source` field. The dashboard form renders a `<select name="source">` from the registry; each row of the interest-credit log shows a **Source** column and carries a hidden `source` on its edit form (the fingerprint recomputed on edit depends on platform + instrument, so the credit keeps its source). An unknown `source` is `400`, never a silent fallback.
- `POST /interest` is a **batch** for one source: parallel `date`/`amount` fields, one pair per row of a grid on the dashboard. The grid starts as a single row (the common case); a client-side "Add row" button clones a row when a batch is wanted. Entirely-blank rows are skipped; a half-filled row or zero filled rows is a `400` that writes nothing — the batch is all-or-nothing on validation, then inserted row by row (idempotent by fingerprint). A single filled row is the former single-entry path unchanged. `POST /interest/update` stays one credit at a time.
- `ledger.Store`'s editable/deletable query (`ManualInterestCredits` / `UpdateManualInterestCredit` / `DeleteManualInterestCredit`) matches `platform IN (manualInterestPlatforms)` instead of a single hard-coded `n26`.
- DIRT is unchanged: `engine.ComputeDIRT` already sums every `interest`-type transaction regardless of platform/instrument, so a new source needs no engine change.

### Out of scope
- A real CSV/PDF parser for any interest source — still manual entry only, by design.
- Non-EUR interest — every supported source pays in euro; `ComputeDIRT` still requires EUR.
- Per-source DIRT breakdown on the dashboard — the DIRT line stays a single combined figure (one tax).

## 11. Feature: Manual RSU-vest entry

**Status:** built (2026-09-06).

### Objective
An RSU vest is the CGT acquisition event (cost basis = vest-date fair market value; the income-tax charge at vest is payroll's, out of scope — §5). E*TRADE's importable-CSV shape is a v1 assumption that often doesn't match a real export, leaving no way to record a vest without hand-building a file. This adds a direct entry path, the same idea as manual interest (§7/§10).

### Shape
- `internal/ingest/etrade` gains `NewRSUVest(symbol, date, quantity, fmvPerShare, currency)` (`manual.go`) — the same `ledger.Transaction` shape `Parse` produces for a `Vest` row: `Type rsu_vest`, `Price` = FMV per share, `Quantity` = shares. `symbol`/`currency` non-empty, `date` `YYYY-MM-DD`, `quantity`/`fmvPerShare` positive; `currency` is upper-cased.
- `POST /rsu` (`handleRSUVest`) — form fields `symbol`, `date`, `quantity`, `fmv`, and `currency` (defaults to `USD`). Validates via `NewRSUVest`, inserts via `ledgerStore.Insert`, `303` to `/` on success, `400` that writes nothing on a bad field, `405` on non-POST — mirrors `handleInterest`.
- A "Log RSU vest" card on the dashboard, next to the interest-entry cards.
- No engine change: a `rsu_vest` already builds a FIFO lot with FMV as cost basis, and a non-EUR vest is restated to euro at its vest-date ECB rate by `toEURPrices` (USD covered in `internal/fx` since 1999). Set the holding to `CGT_ASSET` once it appears.

### Out of scope
- Any RSU platform other than E*TRADE — one manual builder, `PlatformETRADE`. Generalise (a source registry like §10's) if a second platform is needed.
- Batch vest entry — one vest per submit (`POST /interest`'s grid is the batch case; vests are rarer). 
- The income-tax-at-vest side, RSU withholding/sell-to-cover reconstruction — CGT acquisition lot only.

## 12. Feature: Privacy toggle (blur money figures)

**Status:** built (2026-09-06).

### Objective
Read the dashboard in a public space (train, café, screen-share) without every euro figure on show.

### Shape
- A **"Blur €"** button in the top nav (`pageShell`), on every page. Toggling it flips the `localStorage` flag and **reloads** the page, so every figure and chart is rebuilt in the new mode from one code path.
- With `.privacy-mode` on `<html>`: CSS blurs every `.money` span (`formatEUR` and the portfolio P&L percentage of §13 emit their figures inside `<span class="money">`, so this is one class, not a per-figure change) and every `.sensitive` span — the portfolio holdings tables' Symbol and Quantity cells and the remap-form symbol inputs. Hovering one un-blurs just that one. Charts keep their shape but `chartOptions()` drops the value-axis tick labels and the hover tooltips — the parts that spell out amounts. Category axes (dates, instrument names) and the legend stay.
- The flag is stored in `localStorage` (`taxman.privacy`) and the class is applied by the inline `<head>` script **before the body paints**, so a reload never flashes the real numbers. `localStorage` access is wrapped — a private-window failure just means the toggle doesn't persist.
- The stylesheet link carries a `?v=<hash-of-appCSS>`, so a CSS change is picked up on the next load instead of being masked by a cached copy; `/static/app.css` is served `immutable` with an `ETag`.

### Out of scope
- Server-side enforcement — the numbers are still in the HTML; this is a visual screen, not access control.
- Blurring non-monetary figures (share quantities, dates).

- The `/portfolio` holdings table gains a **P&L** column: market value against cost basis as a signed percentage — `(marketValue − costBasis) / costBasis`, one decimal, `+`/`−` sign. The summary card shows the same figure for the portfolio total ("… vs cost").

## 14. Feature: Accountant-verifiable maths reference + BDD scenarios

**Status:** built (2026-09-06). Confirmed via interview-me.

### Objective
Make every calculation the engine performs checkable by someone who
knows Irish investment tax but not Go — as a document to read, and as
executable scenarios that prove the code matches the document.

### Shape
- **`docs/maths.md`** — a plain-English description of every engine
  calculation (lots, FX restatement, FIFO, single-holding CGT,
  year-level CGT aggregation with s.31 netting / s.601 exemption / loss
  carry-forward, exit tax incl. the 41%→38% transition, DIRT,
  effective-dated rate lookup, whole-euro rounding), each rule carrying
  its Irish tax-law citation inline (TCA 1997 sections, Finance Act
  2025, Revenue Tax and Duty Manual part numbers). A dedicated section
  documents what is deliberately **not** computed (s.581, deemed-
  disposal liability, unclassified holdings) and the `UNVERIFIED`
  historical rate entries. No hand-calculated figures: every number
  quoted is engine-produced and pinned in a named feature file or
  golden fixture.
- **`features/*.feature`** — Gherkin scenarios run by
  [`github.com/cucumber/godog`](https://github.com/cucumber/godog)
  (the one new `go.mod` dependency; test/tooling scope only, never in
  the `taxman` binary). Each scenario builds a ledger in plain steps,
  runs one engine computation, and asserts each intermediate and final
  figure. The pinned figures are **engine-generated**: `make
  regen-features` re-runs every scenario and rewrites the numbers in
  the `Then` steps in place. The step vocabulary lives in
  `features/*_test.go`; `TestFeatures` is picked up by `make test` /
  `go test -race ./...`.
- **`make bdd`** runs the scenarios with readable output; **`make
  regen-features`** rebuilds the pinned figures; **`make docs`** renders
  `docs/maths.md` + the feature files into a single self-contained
  `docs/maths.html` (`cmd/gendocs`, standard library only; Markdown
  rendered client-side via a CDN script, degrading to raw text offline)
  for sharing with an accountant or printing to PDF.
- **Drift gate:** `make ci` (and the CI workflow) run `make
  check-features` — regenerating the pinned figures must be a no-op on
  a clean tree. A change to `internal/engine` or `internal/taxrules`
  that moves a number now fails the build unless the worked examples
  are refreshed in the same commit — the same discipline the
  `Always: add or extend a golden fixture` boundary (§6) applies to
  `testdata/golden/`.

### Out of scope
- Independent re-derivation of the figures: the scenarios pin what the
  engine computes (demonstrating the code matches the described
  method), not a separate hand calculation. Cross-checking the figures
  against the taxpayer's own records / an independent tool stays a
  manual step (§1 success criteria).
- Gating `docs/maths.html` freshness in CI — it carries a generation
  date; regenerate it with `make docs` before sharing / at release.
- Any change to `internal/engine`, `internal/taxrules`,
  `internal/audit` — this feature is documentation and tests only.
- A real Gherkin/BDD reporting pipeline (cucumber JSON, HTML reporters)
  beyond `make docs`.

### Boundaries specific to this feature
- **Always:** when a scenario and the engine disagree, fix the engine
  or the `.feature`/`docs` wording — never silently re-pin a number
  without understanding why it moved (the drift gate forces the
  question). Keep `docs/maths.md` citations pointing at a real,
  named Revenue TDM / TCA section.
- **Ask first:** before adding a second test dependency for BDD, or a
  build step for `make docs`.
- **Never:** put a hand-computed tax figure in `docs/maths.md` — quote
  only engine-produced, pinned values (SPEC §6: no LLM tax arithmetic).
